Listening from Google Drive

Kona has no server. Your browser reads music from Google Drive directly. To allow this, you create an OAuth client ID in your own Google Cloud project and enter it in Kona. This is done once and costs nothing.

How it works

Client IDYour own, from your Google Cloud project. Kona contains no one's ID.
PermissionRead-only, drive.readonly. Kona cannot write to Drive.
TokenKept only in this tab's sessionStorage and expires in about an hour. No refresh token is requested.
DestinationOnly the Google API at www.googleapis.com. Nothing is sent anywhere else, including to the developer.
Kept on the deviceTags and covers that have been read, and the tracks of albums set to Keep on device. Clearing the browser's site data removes them.
External scriptsNone. Kona does not use Google's libraries, and the CSP forbids them.

Google's file picker, Picker, could limit access to chosen files, but it requires loading Google's scripts, which conflicts with Kona's rule of loading no external scripts. Kona therefore uses read-only access and lets you choose the folder inside Kona.

1. Create a project and enable the Drive API

  1. Open the Google Cloud console and create a new project from the project selector. Any name will do, for example kona.
  2. Under APIs & Services → Library, search for Google Drive API and enable it.

2. Set up the consent screen

  1. Open APIs & Services → OAuth consent screen and press Get started. In some consoles it is called Google Auth Platform.
  2. Enter an app name, for example Kona, and a support email address.
  3. Choose External as the audience.
  4. Enter a contact email address and create.
  5. Under Audience, check that the publishing status is Testing, and add your Google account under Test users. The app works in testing, so no verification is needed. Only test users can sign in.
  6. Under Data Access, add the scope .../auth/drive.readonly. If you skip this, it is requested at sign-in.

3. Create the client ID

  1. Open Clients → Create client.
  2. Choose Web application as the type.
  3. Under Authorized JavaScript origins, enter the origin of the URL where you open Kona. For the public build this is https://wentolia.github.io.
  4. Under Authorized redirect URIs, enter the URL where you open Kona, exactly. For the public build this is https://wentolia.github.io/kona-open/. The trailing / must match. Copying the text shown on Kona's Drive screen avoids mistakes.
  5. After creation, a client ID ending in …apps.googleusercontent.com is shown. The client secret is not used.

4. Enter it in Kona

  1. In Settings → Other → Google Drive and Spotify, press Enter client ID. Once entered, Drive also appears on the start screen and in the Folders menu.
  2. Paste the client ID and press Save and sign in.
  3. Choose your account on Google's screen. If Google says it hasn't verified this app, press Continue. This only means that the app you created yourself has not been reviewed.
  4. Go to the folder that holds your music and open it.

From then on the folder appears on the start screen. The token expires in about an hour; when it does, sign in again from the notice.

On a phone

  • Tracks are fetched from Drive when played and use mobile data. A FLAC track is about 20 to 40 MB.
  • Albums kept with Keep on device in the track list are stored in the browser and are not downloaded again.
  • Tags and covers stay on the device once read, so later loads are faster.
  • Safari on iPhone may delete data of sites not used for a while. Adding Kona to the Home Screen makes this less likely.

Stopping

  • Sign out in Kona removes the token from this tab.
  • The permission itself can be revoked under third-party connections in your Google account.
  • Deleting the Google Cloud project also invalidates the client ID.
