Listening from Google Drive

Kona has no server. Your browser reads music from Google Drive directly. To allow this, you create an OAuth client ID in your own Google Cloud project and enter it in Kona. This is done once and costs nothing.

Labels below are those of the English interface. Where a control is shown only in Japanese, the Japanese label follows in parentheses.

How it works

Client IDFrom your own Google Cloud project. Kona contains no one's ID.
AccessRead-only (drive.readonly). Kona cannot write to Drive.
TokenKept only in this tab (sessionStorage) and expires after about an hour. No refresh token is requested.
NetworkGoogle APIs (www.googleapis.com) only. Nothing is sent to anyone else, including the developer.
Stored on the deviceTags and covers already read, and tracks of albums you keep on the device. Clearing the browser's site data removes them.
Third-party scriptsNone. Google's libraries are not used, and the CSP forbids them.

Google's file picker could limit access to selected files, but it requires loading Google's scripts, which conflicts with the rule against third-party scripts. Kona therefore uses read-only access and lets you choose the folder inside the app.

1. Create a project and enable the Drive API

  1. Open the Google Cloud console and create a new project from the project selector. Any name will do (for example kona).
  2. Under APIs & Services → Library, find Google Drive API and enable it.

2. Configure the consent screen

  1. Open APIs & Services → OAuth consent screen (or Google Auth Platform) and press Get started.
  2. Enter an app name (for example Kona) and a support email address.
  3. Choose External as the audience.
  4. Enter a contact email address and create.
  5. Under Audience, confirm the publishing status is Testing and add your Google account as a test user. The app can stay in testing; no verification is needed. Only test users can sign in.
  6. Under Data Access, add the scope .../auth/drive.readonly. If omitted, it is requested at sign-in.

3. Create the client ID

  1. Go to Clients → Create client.
  2. Application type: Web application.
  3. Under Authorized JavaScript origins, enter the origin of the URL where you open Kona (for example https://wentolia.github.io).
  4. Under Authorized redirect URIs, enter that URL exactly (for example https://wentolia.github.io/kona-open/), including the trailing /. Copying the string shown in Kona's Drive dialog avoids mistakes.
  5. The client ID (…apps.googleusercontent.com) is shown. The client secret is not used.

4. Enter it in Kona

  1. In Settings → Other → Sources (Google Drive, Spotify), press Enter client ID. Once entered, Drive also appears on the start screen and in the Folders menu.
  2. Paste the client ID and press Save and sign in (保存してサインイン).
  3. Choose your account on Google's screen. If it says Google hasn't verified this app, press Continue; this means only that your own app has not been reviewed.
  4. Navigate to the folder with your music and open it.

The folder is then offered on the start screen. The token expires after about an hour; sign in again from the notice when it does.

On a phone

  • Tracks are downloaded from Drive when played. On mobile data this uses your data allowance (FLAC: roughly 20–40 MB per track).
  • For albums you play often, use Keep on device (端末に残す) in the track list. They are stored in the browser and no longer downloaded.
  • Tags and covers are kept after the first read, so later loads are faster.
  • Safari on iPhone may delete data of sites not used for a while. Adding Kona to the Home Screen makes this less likely.

Stopping

  • Sign out in Kona removes the token from this tab.
  • To revoke access itself, remove Kona under third-party connections in your Google Account.
  • Deleting the Google Cloud project also invalidates the client ID.
